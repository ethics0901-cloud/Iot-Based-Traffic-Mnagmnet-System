PROBLEM 01 DETAILED BREAKDOWN

Problem 1: Fixed-Timing Traffic Signals

INTRODUCTION

Traditional traffic signals run on a fixed green/red duration regardless of actual vehicle count on the road.

PROJECT AIM

To dynamically adjust green/red light duration based on real-time number of vehicles present at an intersection.

GAP IN EXISTING SYSTEM

Existing systems flash the same stretch of green/red at all times, with no responsiveness to actual congestion levels.

ADVANTAGE OF PROPOSED SYSTEM

Reduces unnecessary idle time at signals, improves traffic flow, lowers commute cost and environmental pollution.

LIMITATION / DISADVANTAGE

Requires continuous camera monitoring and processing hardware (Raspberry Pi), adding hardware dependency.

ALGORITHM 04 | DECENTRALIZED CONTROL

Max-Pressure Control Algorithm

★ Final Chosen System Algorithm

STEP-BY-STEP CONTROL LOGIC

  1. Check all roads: System inspects how many vehicles are waiting on each approach lane.
  2. Check vehicles trying to leave: Checks downstream road capacity and departure rates.
  3. Calculate "Pressure": Computes $P = \frac{\text{Vehicles Waiting}}{\text{Distance Monitored}}$ for each direction.
  4. Find highest pressure: The road with the biggest traffic buildup gets highest priority.
  5. Give green light: Allocates green light to the direction with maximum computed pressure.
  6. Repeat continuously: Re-evaluates continuously every 3 seconds for adaptive control.

PYTHON IMPLEMENTATION SNIPPET

def calculate_max_pressure(road1_cars, road1_dist, road2_cars, road2_dist):
    p1 = road1_cars / road1_dist
    p2 = road2_cars / road2_dist
    
    if p1 > p2:
        return "ROAD 1 -> GREEN", p1, p2
    elif p2 > p1:
        return "ROAD 2 -> GREEN", p1, p2
    else:
        return "EQUAL PRESSURE -> NORMAL CYCLE", p1, p2

SENSING & OPTICAL CONSTRAINTS

Sensing Range & Detection Envelope

Interactive optical schematic showing the camera's 30m detection boundary, blind zone, and vehicle occlusion mechanics.

Top-Down Intersection Detection Geometry

MAXIMUM OPERATING DISTANCE: 30 METERS

  • Realistic Operating Range: 15m to 30m per lane (Camera at H = 5.5m–6m).
  • Lens FOV Limit: 60°–75° wide-angle lens captures full approach width up to 30m without radial distortion.
  • Blind Zone: 0m to 3m directly beneath the pole is excluded to avoid steep downward perspective distortion.

WHY RANGE EXISTS: RESOLUTION VS. PIXEL SIZE

  • Vehicle Pixel Budget: At 720p resolution, vehicles beyond 30m shrink below 20×15 pixels.
  • Binarization Failure: Sub-20px objects blend into road surface noise during grayscale thresholding.
  • 4–5 Vehicle Queue: 30m envelope accurately captures the critical waiting queue length.

WHY RANGE EXISTS: VEHICLE OCCLUSION

  • Line-of-Sight Blockage: Tall vehicles (buses/trucks at 10–18m) block smaller cars behind them.
  • Perspective Shadow: Cars hidden inside the optical shadow are invisible to camera perspective beyond 30m.
  • Reliable Density: Bounding detection to 30m prevents phantom shadows from corrupting density count.

Real-Time Operating Cycle & Latency Breakdown

Stage-by-stage execution latency for one complete closed-loop cycle. Total edge computation latency is ~128.3ms.

Edge Control Loop Execution Latency

Total: ~128.3 ms (<0.15s)
1 Image Capture (Pi Camera) 33.3 ms
2 Grayscale & Binarization 30.0 ms
3 Vehicle Count Extraction 45.0 ms
4 Max-Pressure Calculation 5.0 ms
5 UDP Telemetry to NodeMCU 12.0 ms
6 NodeMCU LED Signal Switch 3.0 ms

TOTAL RECALCULATION INTERVAL: 3.0 SECONDS

  • Refresh Frequency: Algorithm recalculates signal timing decisions every 3.0 seconds (2s–5s optimal range).
  • Why 3.0s: Balances instant responsiveness while avoiding signal flicker or instability from over-reacting to 1-second gaps.
  • Low CPU Duty Cycle: ~128ms calculation takes <5% CPU utilization on Raspberry Pi.

SAFETY GUARDRAILS & STABILITY RULES

  • Minimum Green Time: Enforces 10s minimum green duration so signals do not flip erratically.
  • Yellow Clearance: Enforces standard 3s amber transition for driver stopping safety.
  • Background Cloud Sync: Firebase logging runs as asynchronously (every 1 min) without stalling the control loop.
